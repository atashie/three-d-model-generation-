# PrusaSlicer 2.9.7 command line on Windows, 2026-11-11

**Purpose:** evidence for `F6.portability`. Docs/PLAN.md section 4 asks for a second slicer
with an independent file reader to accept the file with the expected bodies and
dimensions. The owner approved this step on 2026-11-11 ("proceed", answering whether to
install PrusaSlicer 2.9.7).

## Install

- **Download:** release `version_2.9.7` (2026-11-02, a security maintenance release),
  asset `PrusaSlicer-2.9.7.zip`, from the GitHub releases page.
- **Hash check:** its SHA-256 equals the digest GitHub publishes,
  `5d4f395aeb6c344b300e0e1be37a0e1931622b642c3c3085eb19cdae211bc008`. See
  `install-hashes.txt`, which also gives the exe hashes.
- **Location:** extracted to the git-ignored `artifacts/tools/prusaslicer-2.9.7/app/`. It
  is a portable copy: no installer ran.
- **Licence:** PrusaSlicer is AGPL-3.0. It is used only as a separate program run as a
  subprocess; no code or profile files are copied into the repository.
- **Program:** `prusa-slicer-console.exe` is the console build. It prints to stdout.

## Settings

- **No Bambu profiles:** PrusaSlicer 2.9.7 ships 104 entries under `resources/profiles`,
  and none is a Bambu printer.
- **So every setting is given explicitly** on the command line:
  - `--bed-shape 0x0,256x0,256x256,0x256` and `--max-print-height 256`;
  - `--nozzle-diameter 0.4`;
  - `--layer-height 0.2` and `--first-layer-height 0.2`;
  - `--filament-diameter 1.75`.

  These are the pinned OrcaSlicer A1 profile's values. No vendor profile is used.

## Behaviour (`measure_prusa.py` → `results.txt`)

| Case | `--info` | `--export-gcode` (explicit settings) |
|---|---|---|
| 20 mm cube | rc 0; 12 facets; manifold yes; 1 part; volume 8000.000488 | rc 0; 100 layers; last Z 20 |
| Cube with one face missing | rc 0; **manifold no, open_edges 3**; volume 6666.67 | **rc 0; 10 layers; last Z 2**: a truncated print |
| 300 × 20 × 5 mm box | rc 0 | **rc 0, no G-code written**: "All objects are outside of the print volume." |
| Unreadable file | rc 1: "Loading of a model file failed." | rc 1 |
| Missing file | rc 1: "No such file" | rc 1 |
| Owner's Roadie, smoothed 60 × 3 mm | rc 0; 59.970630 × 49.404216 × 3.000000; 31,200 facets; manifold yes; 1 part; volume 2277.742188 | rc 0; 15 layers; last Z 3 |
| Owner's Oddie, smoothed 60 × 3 mm | rc 0; 59.986743 × 65.870964 × 3.000000; 29,212 facets; manifold yes; 1 part; volume 5033.670898 | rc 0; 15 layers; last Z 3 |

**Findings:**

1. **Exit codes:** PrusaSlicer reports errors with exit code 1, not OrcaSlicer's negative
   codes. **An exit code of 0 is not success.** A part outside the bed exits 0 and writes
   no G-code, and an open mesh exits 0 with a truncated G-code. The output must be read,
   as with OrcaSlicer.
2. **`--info` gives an independent reader's view of the STL:** size, facet count,
   manifoldness, open edges, part count and volume.
   - For the owner's models, the sizes equal the `tdmg flat` record's `extents_mm` to the
     6 printed decimals.
   - The facet counts equal the triangle counts.
   - The volumes match the record within 5e-6 relative (Roadie 6e-7, Oddie 4.4e-6):
     Roadie 2277.742188 against
     2277.740837, Oddie 5033.670898 against 5033.648715.
3. **Layer counts:** with the explicit settings, the owner's models slice to the same 15
   layers as OrcaSlicer, and the open cube is caught by its layer count (10 against 100).
   G-code layers are marked `;LAYER_CHANGE` and heights `;Z:`.
4. **Repeatability:** two runs on the same STL differ only in line 1,
   `; generated by PrusaSlicer 2.9.7 on <date> at <time> UTC`.

## Limits

- **Coverage:** one PC, STL input only, and the explicit settings above only. No vendor
  profile was used and no 3MF was read.
- **Not done:** PrusaSlicer's G-code was not printed. It is generic (it is not Bambu
  firmware G-code), and it is used only as evidence that a second reader accepts and
  slices the file.

## Addendum: run times, 2026-11-11

**Purpose:** evidence for the rule `slicer.prusa.timeout_s`, the wall-clock limit on each
PrusaSlicer run in `tdmg slice`.

- **Method:** `time_prusa.py` → `timing.txt`. It runs the measured command forms, `--info`
  and `--export-gcode` with the explicit A1 settings above, 5 times each on the 20 mm cube
  and the owner's two smoothed 60 × 3 mm models. Each run is timed with
  `time.perf_counter` around `subprocess.run`, so process start is included. Same PC, same
  pinned install.
- **Result:** every run exited 0. The slowest single run took 1.16 s (the Roadie's
  `--export-gcode`).

| Model | `--info` (min–max, s) | `--export-gcode` (min–max, s) |
|---|---|---|
| 20 mm cube | 0.12–0.28 | 0.18–0.20 |
| Roadie, 31,200 facets | 0.16–0.67 | 1.09–1.16 |
| Oddie, 29,212 facets | 0.15–0.17 | 0.85–0.91 |

**Limits:** one PC, small models only. No model near the 1,000,000-triangle budget and
no slower machine was timed.

## Addendum: `F6.portability` through `tdmg slice`, 2026-11-11

**Purpose:** portability plan Task 3 (`docs/plans/2026-11-11-portability-check.md`): run
the implemented check (`slice-4`) on the owner's models and on the bad-file controls.
Same PC, the pinned OrcaSlicer 2.5.0 and PrusaSlicer 2.9.7, full tree checks.

**Controls** (`controls_portability.py` → `controls.txt`). The script builds minimal
flat folders and calls `make_slice` with both slicers:

| Case | OrcaSlicer | `F6.portability` | G-code |
|---|---|---|---|
| 20 mm cube | exit 0, 100 layers | PASS: 1 part, 12 facets, volume 8000.000488, 100 layers | written |
| Cube with one face missing | exit 0, 10 layers (`F6.layer_count` FAIL) | FAIL: "reads model.stl as not manifold (open_edges 3)" | both files quarantined as `.failed` |
| 300 × 20 × 5 mm box | exit −50 (`F6.slicer_exit` FAIL) | FAIL: "--export-gcode exited 0 but wrote no G-code: All objects are outside of the print volume." | none |

The cube is NOT CERTIFIED only because its minimal flat folder has no F1/F2 checks; the
script does not run `tdmg flat`.

**Owner models.** `tdmg flat` was re-run with the current code
(`artifacts/flat-runs/{roadie-tol30,oddie}-60x3-s4`, git-ignored). The STLs are
byte-identical to the `-s3` ones, so the Roadie is the same file the owner printed.
`tdmg slice` with both slicers (`artifacts/slice-runs/*-60x3-printable`):

| Model | Verdict | Edge coverage, worst (allowance) | Overprint, worst | Portability |
|---|---|---|---|---|
| Roadie | **PRINTABLE** | 0.231 mm, first layer (0.275) | 0.013 mm | PASS: 1 part, 31,200 facets, 59.970630 × 49.404216 × 3, volume 2277.742188, 15 layers |
| Oddie | **PRINTABLE** | 0.222 mm, first layer (0.275) | 0.013 mm | PASS: 1 part, 29,212 facets, 59.986743 × 65.870964 × 3, volume 5033.670898, 15 layers |

Every required check is PASS; `F3.thin_regions` (information only) is UNKNOWN. The
slice_ids are `7a9836d9…` (Roadie) and `33c470ac…` (Oddie).

**What PRINTABLE does not mean:** the acceptance tolerance is still a hypothesis, no
calibration print has been measured, and strength is not judged. Both slicers read STL
with admesh, so this shows that a second slicer accepts and slices the file, not that an
independent reader agrees.

## Addendum: corrections after the Codex review, 2026-11-11

See `research/reviews/2026-11-11-portability/README.md`.

- **Settings (corrects "So every setting is given explicitly" above):** only the bed
  shape and height, nozzle diameter, layer and first-layer heights and filament diameter
  are given. Every other setting is PrusaSlicer 2.9.7's default. The Roadie's PrusaSlicer
  G-code records `fill_density = 20%`, `elefant_foot_compensation = 0` and
  `perimeter_generator = arachne`; the OrcaSlicer A1 run used 15%, 0.075 and classic.
- **What the G-code shows:** layer markers alone do not show a complete slice. The check
  now also reads the motion. Facts it relies on, measured on all 14 PrusaSlicer G-code
  files written here (owner models, cube, open cube): each ends with
  `; prusaslicer_config = end`; each uses G90 and M82 with `G92 E0` resets and only
  G0/G1 moves; no X, Y or Z word has more than 3 decimals. On the owner models every
  layer has 925 or more extruding moves, all at their layer's height (largest difference
  4e-16 mm). The parser's total filament equals the file's own
  `; filament used [mm]` line (Roadie 814.64, Oddie 1367.12).
- **Mutations** (`mutations_portability.py` → `mutations.txt`): the real Roadie and Oddie
  G-code PASS; cut after the last `;Z:`, cut within the last layer, comments only (with
  and without the closing line), the last layer's extrusion removed, M83, and one
  layer's Z raised all FAIL.
- **Re-run:** the owner models stay PRINTABLE with the same slice_ids; the controls give
  the same verdicts (`controls.txt`, re-run with the fixed code).

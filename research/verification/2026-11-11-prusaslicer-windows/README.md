# PrusaSlicer 2.9.7 command line on Windows, 2026-11-11

**Purpose:** evidence for `F6.portability`. Docs/PLAN.md section 4 asks for a second slicer
with an independent file reader to accept the file with the expected bodies and
dimensions. The owner approved this step on 2026-11-11 ("proceed", answering whether to
install PrusaSlicer 2.9.7).

## Install

- **Download:** release `version_2.9.7` (2026-11-02, a security maintenance release),
  asset `PrusaSlicer-2.9.7.zip`, from the GitHub releases page.
- **Hash check:** its SHA-256 equals the digest GitHub publishes,
  `5d4f395aeb6c344b300e0e1be37a0e1931622b642c3c3085eb19cdae211bc008`. See
  `install-hashes.txt`, which also gives the exe hashes.
- **Location:** extracted to the git-ignored `artifacts/tools/prusaslicer-2.9.7/app/`. It
  is a portable copy: no installer ran.
- **Licence:** PrusaSlicer is AGPL-3.0. It is used only as a separate program run as a
  subprocess; no code or profile files are copied into the repository.
- **Program:** `prusa-slicer-console.exe` is the console build. It prints to stdout.

## Settings

- **No Bambu profiles:** PrusaSlicer 2.9.7 ships 104 entries under `resources/profiles`,
  and none is a Bambu printer.
- **So every setting is given explicitly** on the command line:
  - `--bed-shape 0x0,256x0,256x256,0x256` and `--max-print-height 256`;
  - `--nozzle-diameter 0.4`;
  - `--layer-height 0.2` and `--first-layer-height 0.2`;
  - `--filament-diameter 1.75`.

  These are the pinned OrcaSlicer A1 profile's values. No vendor profile is used.

## Behaviour (`measure_prusa.py` → `results.txt`)

| Case | `--info` | `--export-gcode` (explicit settings) |
|---|---|---|
| 20 mm cube | rc 0; 12 facets; manifold yes; 1 part; volume 8000.000488 | rc 0; 100 layers; last Z 20 |
| Cube with one face missing | rc 0; **manifold no, open_edges 3**; volume 6666.67 | **rc 0; 10 layers; last Z 2**: a truncated print |
| 300 × 20 × 5 mm box | rc 0 | **rc 0, no G-code written**: "All objects are outside of the print volume." |
| Unreadable file | rc 1: "Loading of a model file failed." | rc 1 |
| Missing file | rc 1: "No such file" | rc 1 |
| Owner's Roadie, smoothed 60 × 3 mm | rc 0; 59.970630 × 49.404216 × 3.000000; 31,200 facets; manifold yes; 1 part; volume 2277.742188 | rc 0; 15 layers; last Z 3 |
| Owner's Oddie, smoothed 60 × 3 mm | rc 0; 59.986743 × 65.870964 × 3.000000; 29,212 facets; manifold yes; 1 part; volume 5033.670898 | rc 0; 15 layers; last Z 3 |

**Findings:**

1. **Exit codes:** PrusaSlicer reports errors with exit code 1, not OrcaSlicer's negative
   codes. **An exit code of 0 is not success.** A part outside the bed exits 0 and writes
   no G-code, and an open mesh exits 0 with a truncated G-code. The output must be read,
   as with OrcaSlicer.
2. **`--info` gives an independent reader's view of the STL:** size, facet count,
   manifoldness, open edges, part count and volume.
   - For the owner's models, the sizes equal the `tdmg flat` record's `extents_mm` to the
     6 printed decimals.
   - The facet counts equal the triangle counts.
   - The volumes match the record within 5e-6 relative (Roadie 6e-7, Oddie 4.4e-6):
     Roadie 2277.742188 against
     2277.740837, Oddie 5033.670898 against 5033.648715.
3. **Layer counts:** with the explicit settings, the owner's models slice to the same 15
   layers as OrcaSlicer, and the open cube is caught by its layer count (10 against 100).
   G-code layers are marked `;LAYER_CHANGE` and heights `;Z:`.
4. **Repeatability:** two runs on the same STL differ only in line 1,
   `; generated by PrusaSlicer 2.9.7 on <date> at <time> UTC`.

## Limits

- **Coverage:** one PC, STL input only, and the explicit settings above only. No vendor
  profile was used and no 3MF was read.
- **Not done:** PrusaSlicer's G-code was not printed. It is generic (it is not Bambu
  firmware G-code), and it is used only as evidence that a second reader accepts and
  slices the file.

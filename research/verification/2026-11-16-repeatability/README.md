# Repeatability baseline, 2026-11-16

Restructure plan (`docs/plans/2026-11-16-restructure.md`), Task 0. The question: if we
run today's pipeline twice on the same inputs, which output files come out byte for
byte the same, and which fields of the JSON records change?

The answer sets the comparison for the rebuild proof (Task 9). That proof may ignore
the fields in the table below, and no others.

## What was run

- **Machine:** the Windows PC (Windows 11 Pro 10.0.26200, x64, Python 3.13.1).
- **Date:** 2026-11-16, 15:11 to 15:32 local time. Run A, then run B, one after the
  other. Nothing else heavy ran at the same time.
- **Code:** commit `f17d56f`, plus the new `scripts/repeat_runs.py` (not yet committed
  when it ran; it only drives the CLI).
- **Slicers:** the pinned OrcaSlicer 2.5.0 (`artifacts/tools/orcaslicer-2.5.0`) and
  PrusaSlicer 2.9.7 (`artifacts/tools/prusaslicer-2.9.7`). Every slice verified the app
  tree (no `--skip-tree-check`).
- **Command:**

  ```bash
  uv run python scripts/repeat_runs.py --out artifacts/repeat-runs/2026-11-16 \
      --slicer-dir artifacts/tools/orcaslicer-2.5.0 \
      --prusaslicer-dir artifacts/tools/prusaslicer-2.9.7 \
      --images-dir C:/Users/arikt/Downloads/three-d-test
  ```

- **Outputs:** `artifacts/repeat-runs/2026-11-16/run-a` and `run-b` (git-ignored; on
  the PC only). The script's full report is `report.md` in this folder (a copy) and
  `report.json` next to the runs.

## Where the inputs came from

The script starts from the six slice records in `artifacts/slice-runs/fd8/` and follows
each one back by the SHA-256 that it records. No parameter was typed in by hand.

| Job | Chain of records |
|---|---|
| R1 Roadie | `slice-runs/fd8/roadie-r1/slice.json` -> `flat-runs/roadie-tol30-60x3-s5/flat.json` -> `selection-runs/roadie-tol30/selection.json` |
| R1 Oddie | `slice-runs/fd8/oddie-r1/slice.json` -> `flat-runs/oddie-60x3-s5/flat.json` -> `selection-runs/oddie/selection.json` |
| Each of the 4 owner plans | `slice-runs/fd8/<plan>/slice.json` -> `colored-runs/<plan>/colored.json` -> `colors-runs/<plan>/colors.json` (with its config, found by `config_sha256` in `colors-runs/configs/`) -> the selection |
| Strip | `test-strips/strip.json` (only its timeout source and tree check) |

The source images in `Downloads/three-d-test` matched `input.file_sha256` in both
`selection.json` files. The selection controls (`--tolerance 30`, `--remove-at 60,396`,
`--keep-at 470,470` for Roadie; none for Oddie) and the instructions text come from
each `selection.json`. All other values came from their rules or defaults, as the
records say. The four configs are `keep.yaml` (Roadie keep), `merge-blues.yaml`
(Oddie merge blues), `keep-merge-blues-greens.yaml` (Oddie keep), and none (Roadie drop).

Every step exited as it did on the recorded run. Two color slices exit 1 in both runs,
as recorded in `slice-runs/fd8/<plan>.txt`: their glue plates are not PRINTABLE.

## Result

**159 output files. 119 are byte-identical. 40 differ.** All 40 differences have one
cause: **the slicers write the time of slicing into the G-code.**

- Each OrcaSlicer G-code differs only in line 2:
  `; generated by OrcaSlicer 2.5.0 on 2026-11-16 at 15:11:34` (local time).
- Each PrusaSlicer G-code (`prusaslicer.portability-only.gcode.txt`, and its `.failed`
  form) differs only in line 1: `; generated by PrusaSlicer 2.9.7 on 2026-11-16 at
  20:11:42 UTC`.
- Every other line of every G-code is the same (for example, 1 of 27136 lines differs
  in the Roadie R1 G-code).
- The records that hold the hashes of those G-code files (`slice.json`, `strip.json`)
  then differ in those hash fields, and only there.

**Byte-identical in both runs** (by stage):

- `tdmg select`: `selection.json`, `mask.png`, `cutout.png`, `preview.png`.
  Both `selection.json` files are also byte-identical to the originals in
  `artifacts/selection-runs/` (the SHA-256 that `colors.json` records).
- `tdmg flat`: `model.stl`, `outline.png`, `flat.json`.
- `tdmg colors`: `colors.json`, `labels.png`, `regions.png`.
- `tdmg flat --colors`: every STL, `model.3mf`, `palette.json`, `top.png`, `parts.png`,
  `colored.json`.
- `tdmg slice`: `orca-input.3mf`, `plate_1.statistics.json`, `filaments/*.json`.
  In `slice.json`, `slice_id` and `colorslice_id` are the same, and so is each G-code's
  `normalised_sha256` (the hash with the timestamp line taken out).
- `tdmg strip`: the STLs, `skin/model.3mf`, `palette.json`, `results-template.md`,
  statistics and filament files. In `strip.json`, `strip_id` and `geometry_id` are the
  same.
- The command output of every step is the same, once the run folder name is replaced.

## Fields that differ between two runs

These are the fields the rebuild proof may ignore. `<plate>` is a glue plate name, such
as `glue-base` or `glue-color-1-f5f5f5`. `<gcode file>` is the path of a G-code file
inside the output folder: `plate_1.gcode`, `face-up/plate_1.gcode`,
`face-down/plate_1.gcode`, `<plate>/plate_1.gcode`,
`prusaslicer.portability-only.gcode.txt`, `<plate>/prusaslicer.portability-only.gcode.txt`,
or one of these with `.failed` added.

| Record file | JSON path | Reason (measured) |
|---|---|---|
| `slice.json` (R1) | `$.gcode.sha256` | OrcaSlicer G-code timestamp (line 2) |
| `slice.json` (R1 and color) | `$.portability.gcode.sha256` | PrusaSlicer G-code timestamp (line 1) |
| `slice.json` (color) | `$.faces.up.gcode.sha256`, `$.faces.down.gcode.sha256` | OrcaSlicer G-code timestamp (line 2) |
| `slice.json` (color) | `$.glue.plates.<plate>.gcode.sha256` | OrcaSlicer G-code timestamp (line 2) |
| `slice.json` (color) | `$.glue.plates.<plate>.portability.gcode.sha256` | PrusaSlicer G-code timestamp (line 1) |
| `slice.json` (R1 and color) | `$.outputs.<gcode file>` (the file's SHA-256) | the G-code timestamp of that file |
| `strip.json` | `$.clearance.plates.base.gcode.sha256`, `$.clearance.plates.pieces.gcode.sha256`, `$.skin.face.gcode.sha256` | OrcaSlicer G-code timestamp (line 2) |
| `strip.json` | `$.outputs.<gcode file>` (`clearance/slice/base/plate_1.gcode.failed`, `clearance/slice/pieces/plate_1.gcode`, `skin/slice/face-up/plate_1.gcode`) | OrcaSlicer G-code timestamp (line 2) |

The G-code files themselves differ in those timestamp lines only. No other field of
`selection.json`, `flat.json`, `colors.json`, `colored.json`, `palette.json`,
`slice.json` or `strip.json` differed.

## Limits

- One machine, one day, two runs. The runs were 10 minutes apart, so the timestamps
  differ only in minutes. A run on another day changes the date in the same lines.
  Whether anything else changes on another day was not run.
- Another machine (the Mac, or another OS) was not tested. Byte-identical here does
  not show byte-identical across machines.
- The runs did not compare against the original runs of 2026-11-10 to 2026-11-16,
  except for the two `selection.json` files and the Roadie `model.3mf` above.

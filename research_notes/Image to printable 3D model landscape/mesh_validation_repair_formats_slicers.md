## 1. Which Python-accessible libraries do mesh QA and repair, and what exactly can each do?

### Takeaway
On arm64 macOS the practical, pip-installable, permissively-licensed core is `trimesh` (MIT, pure Python) + `manifold3d` (Apache-2.0, guaranteed-manifold booleans/SDF meshing) + `lib3mf` (BSD, official 3MF writer with manifold/orientation validation) + `open3d` (MIT) + `point-cloud-utils` (MIT); the strongest repair engines are copyleft or source-available (`pymeshlab` GPL-3, `pymeshfix` GPL/AGPL with a commercial restriction, `meshlib` free only for non-commercial use, CGAL bindings GPL-3). `bpy` works only on a pinned Python version, `pyopenvdb` from PyPI does not work on macOS at all, and `admesh`/`pycork` Python bindings are effectively dead on this platform.

## 2. What checks define "printable"? Definitions, how to compute each, and the thresholds the industry uses

### Takeaway
The conformance core is the 3MF specification's MUST set for `type="model"` meshes: every edge shared by exactly two triangles, consistent orientation, outward normals (positive volume); self-intersections and zero-area triangles are only SHOULD-NOT quality warnings. Each check has a direct deterministic implementation in several libraries (listed below); dimensional thresholds (wall thickness, feature size, size limits) come from service bureaus and slicer defaults and are covered in the sub-agent findings appended at the end of this section.

### Cited Findings
**Spec-level definitions (VERIFIED from the 3MF core spec via sub-agent, [spec_core](https://github.com/3MFConsortium/spec_core/blob/master/3MF%20Core%20Specification.md))**
- For meshes under objects of type "model" or "solidsupport": "Every triangle edge in the mesh shares common vertex endpoints with the edge of exactly 1 other triangle" (manifold edges); "Every pair of adjacent triangles within the mesh MUST have the same orientation of the face normal"; "All triangles MUST be oriented with normals that point away from the interior of the object".
- Fill rule: "In 3MF, the fill rule applied is always the Positive fill rule"; "Meshes with negative volume will not be printed (or will become voids)".
- "Producers SHOULD NOT produce self-intersections or overlapping objects" and "consumers MUST accept self-intersecting meshes and overlapping objects"; "All triangles SHOULD have a non-zero area".
- `lib3mf` `MeshObject.IsManifoldAndOriented()` "Retrieves, if an object describes a topologically oriented and manifold mesh, according to the core spec" — VERIFIED [lib3mf docs](https://lib3mf.readthedocs.io/en/latest/source/Cpp/lib3mf_MeshObject.html); VERIFIED-LOCAL it returns True for the closed cube and False for the open one.

**Check-by-check: definition → implementation**
- Watertight/closed (no boundary edges): trimesh `is_watertight` ("every edge is included in two faces") — [trimesh.base](https://trimesh.org/trimesh.base.html); Open3D `is_watertight` = vertex-manifold + edge-manifold without boundary + not self-intersecting — [TriangleMesh.h](https://raw.githubusercontent.com/isl-org/Open3D/main/cpp/open3d/geometry/TriangleMesh.h); PyMeshLab `get_topological_measures()['boundary_edges'] == 0` and `number_holes` (VERIFIED-LOCAL keys); igl `boundary_loop_all` / `boundary_facets` (VERIFIED-LOCAL); MeshLib `isClosed`, `findRightBoundary` (VERIFIED-LOCAL); lib3mf `IsManifoldAndOriented`; PrusaSlicer CLI `--info` prints `manifold = yes|no` and `open_edges = N` (see §6).
- Edge-manifold (each edge in ≤2 faces): Open3D `is_edge_manifold(allow_boundary_edges)` / `get_non_manifold_edges`; PyMeshLab `non_two_manifold_edges`, `is_mesh_two_manifold`; igl `is_edge_manifold`; MeshLib `findMultipleEdges`/`hasMultipleEdges` (VERIFIED-LOCAL); manifold3d `Manifold(mesh).status() == Error.NotManifold` (VERIFIED-LOCAL).
- Vertex-manifold ("A vertex is manifold if its star is edge-manifold and edge-connected"): Open3D `is_vertex_manifold`/`get_non_manifold_vertices` — [TriangleMesh.h](https://raw.githubusercontent.com/isl-org/Open3D/main/cpp/open3d/geometry/TriangleMesh.h); PyMeshLab `non_two_manifold_vertices`; igl `is_vertex_manifold`; MeshLib `duplicateMultiHoleVertices` (repair). trimesh has no direct vertex-manifold test (VERIFIED absence on the base page).
- Consistent winding / orientability: trimesh `is_winding_consistent`; Open3D `is_orientable` ("the triangles can be oriented in such a way that all normals point towards the outside") and `orient_triangles`; igl `bfs_orient`, `orientable_patches`; PyMeshLab `meshing_re_orient_faces_coherently`; CGAL PMP `orient_polygon_soup` (VERIFIED-LOCAL).
- Outward normals / positive signed volume: trimesh `is_volume` (watertight + consistent winding + outward normals) and `volume` sign; `fix_inversion` "Check to see if a mesh has normals pointing out" — [trimesh.repair](https://trimesh.org/trimesh.repair.html); CGAL PMP `is_outward_oriented` (VERIFIED-LOCAL); igl `orient_outward`; Open3D `get_volume` (requires watertight+orientable); manifold3d `volume()` (VERIFIED-LOCAL 1.0 on unit cube); PrusaSlicer `--info` `volume =`.
- No self-intersections: Open3D `is_self_intersecting`/`get_self_intersecting_triangles` (pairwise test); PyMeshLab `compute_selection_by_self_intersections_per_face`; MeshLib `findSelfCollidingTriangles` (VERIFIED-LOCAL 0 on a clean cube); CGAL PMP `does_self_intersect`/`self_intersections`; igl `copyleft.cgal.remesh_self_intersections` (exact, GPL); igl `tri_tri_intersection_test_3d`. - No degenerate/zero-area faces: trimesh `nondegenerate_faces(height=1e-08)` ("faces without 3 unique vertex indices") — [trimesh.base](https://trimesh.org/trimesh.base.html); PyMeshLab `meshing_remove_null_faces`; Open3D `remove_degenerate_triangles` (only repeated-vertex-index triangles); MeshLib `findDegenerateFaces(mesh, critAspectRatio)` (VERIFIED-LOCAL); igl `doublearea` (compute areas, threshold). ### Inferences
- A deterministic gate can be expressed as ordered predicates: finite coordinates → no degenerate/duplicate faces → edge-manifold → vertex-manifold → closed → orientable & consistently wound → positive volume → (warn) self-intersections → component policy → thickness → bbox fits printer. The first seven map exactly onto lib3mf `IsManifoldAndOriented` plus Open3D/PyMeshLab checks; a mesh accepted by `manifold3d.Manifold(...)` with `NoError` satisfies the 3MF MUST rules by construction (same definition).
- Because the 3MF spec says consumers MUST accept self-intersecting meshes, self-intersection should be a warning that triggers a "make solid" path rather than a hard reject.

### Gaps
- The Thingi10K paper PDF (12 MB) exceeded the fetch limit; percentages are from the dataset README/HF card, not the paper text.
- No single industry-wide numeric "printable" standard exists; thresholds below are vendor-specific.

### 2b. Standardized checklists and thresholds (Blender 3D-Print Toolbox, service bureaus, Netfabb/Microsoft, slicer auto-repair and thin-wall logic)

**Takeaway (2b).** Blender's toolbox encodes the de-facto checklist with concrete defaults (zero threshold 1e-4, thickness 1 mm, overhang 45°, sharp edge 160°, non-planar 5° in the 2026 extension); bureau rules converge on ≥0.8 mm walls (1.2–2.5 mm recommended), ≥1.2–2 mm features, Ø≥1.5–2 mm holes, ≤10 mm bridges, 45° overhangs, 0.5 mm clearances, ±0.3–0.5% tolerance; slicers do not fill holes on import (PrusaSlicer explicitly disabled it) but close small cracks per layer (`slice_closing_radius` 0.049 mm) and, except OrcaSlicer ≥2.4.x, depend on the Windows-only Microsoft/Netfabb repair API for "Fix model".

**Cited Findings (2b)**

*Blender 3D-Print Toolbox (checks and defaults)*
- Manual (Blender ≤4.1, VERIFIED via the manual repo [3d_print_toolbox.rst](https://projects.blender.org/blender/blender-manual/raw/branch/blender-v4.1-release/manual/addons/mesh/3d_print_toolbox.rst)): "In order to correctly slice a mesh, it needs to be 'watertight'… there should be no edges or faces sticking out." ## 3. Repair strategies and trade-offs; when repair destroys detail and how to measure it

### Takeaway
Local topological repairs (dedupe, degenerate removal, winding fix, small-hole fill, non-manifold edge/vertex splitting) preserve geometry but cannot guarantee a solid; global "make solid" methods (MeshFix, voxel/SDF rebuild via OpenVDB/MeshLib/PyMeshLab/manifold3d level-set, Watertight-Manifold/ManifoldPlus, Poisson) always produce a closed manifold but resample the surface, erase thin/internal detail, and inflate triangle counts; detail loss is measured deterministically with two-sided Hausdorff/Chamfer distance (PyMeshLab, Open3D, pcu, igl) plus volume/area/genus/component deltas.

### Cited Findings
- Hole filling: trimesh `fill_holes` fans, "may result in bad answers if the holes are non convex" and only single-triangle/quad holes ([trimesh.repair](https://trimesh.org/trimesh.repair.html), [trimesh.base](https://trimesh.org/trimesh.base.html)); `stitch` creates a fan over a boundary; PyMeshLab `meshing_close_holes(maxholesize=30, selfintersection=True, refinehole=False, refineholeedgelen=3%)` closes holes with fewer boundary edges than the threshold and uses a heuristic to avoid self-intersecting fill faces ([filter list](https://pymeshlab.readthedocs.io/en/latest/filter_list.html)); MeshLib `fillHole`, `fillHoleNicely`, `fillHoleTrivially`, `fillHolesWithExtraPoints`, `buildCylinderBetweenTwoHoles` (VERIFIED-LOCAL); CGAL PMP `triangulate_hole`, `triangulate_and_refine_hole`, `triangulate_refine_and_fair_hole` (VERIFIED-LOCAL); MeshFix fills via `fill_small_boundaries()` ([pymeshfix README](https://github.com/pyvista/pymeshfix)).
- Normal unification: trimesh `fix_normals` ("Really only meaningful on watertight meshes", `multibody=True` to fix each body) and `fix_winding`; PyMeshLab `meshing_re_orient_faces_coherently` (non-orientable surfaces "can't be fully fixed, and the result may be inverted") then `meshing_invert_face_orientation(forceflip=False)` to orient outward; Open3D `orient_triangles` (only if orientable); igl `bfs_orient` + `orient_outward`; CGAL `orient_polygon_soup`; ADMesh `stl_fix_normal_directions` (used by PrusaSlicer at STL load, see §6).
- Duplicate/degenerate removal: see §2 implementations; Open3D notes degenerate triangles "are usually the product of removing duplicated vertices", so order matters (merge → remove degenerate → remove duplicate faces) — [TriangleMesh.h](https://raw.githubusercontent.com/isl-org/Open3D/main/cpp/open3d/geometry/TriangleMesh.h).
- Non-manifold repair: PyMeshLab `meshing_repair_non_manifold_edges(method='Remove Faces'|'Split Vertices')` and `meshing_repair_non_manifold_vertices(vertdispratio=0)` (splits vertices "until the mesh is 2-manifold"); Open3D `remove_non_manifold_edges` deletes the smallest-area incident triangles until ≤2 remain (creates holes that must then be filled); igl `split_nonmanifold`, `extract_manifold_patches`; MeshLib `fixMultipleEdges`, `duplicateMultiHoleVertices`; manifold3d `Mesh.merge()` fixes "slightly non-manifold meshes" (split vertices) — VERIFIED-LOCAL.
- Small components: PyMeshLab by diameter (default 10% of bbox) or face count (25); pymeshfix drops all but the largest by default (VERIFIED-LOCAL); CGAL `keep_largest_connected_components`; trimesh `split()` then filter by `volume`/`area`.
- Remeshing: PyMeshLab `meshing_isotropic_explicit_remeshing(targetlen=1%, featuredeg=30, checksurfdist=True, maxsurfdist=1%)` ([filter list](https://pymeshlab.readthedocs.io/en/latest/filter_list.html)); MeshLib `remesh`; CGAL `isotropic_remeshing` (VERIFIED-LOCAL); Open3D/trimesh/manifold3d `refine*` subdivision; decimation via fast-simplification/pyfqmr/Open3D/PyMeshLab/MeshLib/manifold3d `simplify`.
- Voxelization + marching cubes / "make solid": PyMeshLab `generate_resampled_uniform_mesh(cellsize, offset, mergeclosevert, discretize, multisample, absdist)` produced a closed two-manifold from a 20-face icosphere-derived test (VERIFIED-LOCAL); MeshLib `offsetMesh(mesh, 0.0, OffsetParameters(voxelSize=…))` rebuilt a 12-face cube as 5,292 faces with volume preserved at 1.0 (VERIFIED-LOCAL), plus `generalOffsetMesh`, `mcOffsetMesh`, `meshToLevelSet`→`gridToMesh`, `marchingCubes`, `voxelBooleanUnite` (VERIFIED-LOCAL names); OpenVDB `meshToLevelSet` requires "a closed surface but not necessarily a manifold surface", tolerates self-intersections/degenerate faces and ignores orientation ([MeshToVolume.h](https://www.openvdb.org/documentation/doxygen/MeshToVolume_8h.html)), then `convertToPolygons(adaptivity)` ([Python docs](https://www.openvdb.org/documentation/doxygen/python.html)); manifold3d `Manifold.level_set(sdf, bounds, edge_length)` meshes any SDF into a guaranteed-manifold mesh ("improves significantly over Marching Cubes") (VERIFIED-LOCAL + [README](https://github.com/elalish/manifold)); SDF sources for open/soup input: igl/pcu fast winding number (`signed_distance_to_mesh`), pysdf robust ray parity ([README](https://github.com/sxyu/sdf)); pcu `make_mesh_watertight` (Watertight Manifold algorithm; 10 → 10,960 faces on a cube, VERIFIED-LOCAL); ManifoldPlus CLI (non-commercial licence) ([GitHub](https://github.com/hjwdzh/ManifoldPlus)); scikit-image `marching_cubes` + trimesh `voxelized(pitch)` as a pure-permissive fallback (VERIFIED installable).
- Poisson reconstruction: Open3D `create_from_point_cloud_poisson(pcd, depth=8)` "from an oriented point cloud" ([API](https://www.open3d.org/docs/latest/python_api/open3d.geometry.TriangleMesh.html)); PyMeshLab `generate_surface_reconstruction_screened_poisson` (VERIFIED-LOCAL name). Requires oriented normals; output is a smooth closed surface.
- Boolean union of overlapping shells: manifold3d booleans are "guaranteed manifold output" but require manifold inputs ("you'll get an error status if the imported mesh isn't manifold") — [README](https://github.com/elalish/manifold); trimesh `union(check_volume=True)` raises unless all inputs are "watertight positive volumes" ([trimesh.boolean](https://trimesh.org/trimesh.boolean.html)); MeshLib `boolean`/`selfBoolean`/`voxelBooleanUnite` ("voxel-based mode for messy input") — [README](https://github.com/MeshInspector/MeshLib); igl `copyleft.cgal.mesh_boolean` (exact arithmetic, GPL); Cork (dormant).
- Self-intersection removal: MeshFix removes all self-intersections ([MeshFix README](https://github.com/MarcoAttene/MeshFix-V2.1)); MeshLib `fixSelfIntersections` with `FixSelfIntersectionMethod` (VERIFIED-LOCAL); igl `remesh_self_intersections` + `outer_hull`/`peel_winding_number_layers`; PyMeshLab select-self-intersecting → `meshing_remove_selected_faces` → `meshing_close_holes`.
- Measuring detail loss: PyMeshLab `get_hausdorff_distance` samples one mesh and finds closest points on the other, storing distances as vertex quality; parameters `samplenum`, `maxdist=50%`; returns RMS/max/mean/min plus `diag_mesh_0/1` for normalisation (VERIFIED-LOCAL); it is one-sided per call. Open3D `PointCloud.compute_point_cloud_distance` (point-to-point after `sample_points_uniformly`/`poisson_disk`) — VERIFIED-LOCAL; pcu `hausdorff_distance`, `one_sided_hausdorff_distance`, `chamfer_distance` on point sets, `closest_points_on_mesh` for point-to-surface — [README](https://github.com/fwilliams/point-cloud-utils); igl `hausdorff` (VERIFIED-LOCAL name). Topological deltas: `genus`/`euler_number`, component count, boundary count; metric deltas: `volume`, `area` (all libraries above).

### Inferences
- Repair ladder that preserves the most detail first: (1) finite check + merge vertices + drop degenerate/duplicate faces; (2) orient + fix inversion; (3) fill small holes (PyMeshLab `maxholesize`, MeshLib `fillHoleNicely`); (4) split/repair non-manifold edges and vertices then re-fill; (5) component policy; (6) only if still not a valid volume or self-intersecting: global rebuild (MeshFix for scan-like meshes; SDF/voxel rebuild for AI-generated soups), then decimate back toward the original triangle budget.
- Voxel/SDF rebuilds destroy features smaller than ~2 voxels and merge nearby surfaces; the voxel size should be tied to the printer's minimum feature size (e.g. half the nozzle width) so that what is lost would not have printed anyway. This is an engineering inference, not a cited rule.
- Measure every repair with two-sided Hausdorff (run PyMeshLab both directions, or pcu `hausdorff_distance`) normalised by bbox diagonal, plus |ΔV|/V and Δgenus; accept if max distance < layer height or nozzle width — threshold values are a design choice (no vendor standard found).

### Gaps
- No primary source quantifies detail loss of specific algorithms; the comparisons above are qualitative from library docs.
- MeshLib `OffsetParameters` defaults and the exact `voxelSize` semantics were not fetched (only exercised locally).

## 4. Wall-thickness and thin-feature analysis: algorithms and ready-made implementations

### Takeaway
Three deterministic families exist in Python: ray casting along inverted normals (trimesh `method='ray'`, MeshLib `computeRayThicknessAtVertices`, DIY with Open3D `RaycastingScene`), inscribed/tangent spheres (trimesh `max_sphere`, MeshLib `computeInSphereThicknessAtVertices`), and shape-diameter-function cone sampling (PyMeshLab); they give different numbers on the same geometry (unit cube: ray 1.0 vs max-sphere 0.667 at face centres; 1.732 vs 0.866 at vertices), so the gate must fix one definition and threshold.

### Cited Findings
- trimesh `proximity.thickness(mesh, points, exterior=False, normals=None, method='max_sphere')`, "One of 'max_sphere' or 'ray'", returns `(n,)` thickness; `max_tangent_sphere(mesh, points, inwards=True, normals=None, threshold=1e-06, max_iter=100)` finds a sphere tangent at the point and one more point with no other intersections (Inui, Umezu & Shimane 2016 shrinking-sphere algorithm); `longest_ray(mesh, points, directions)`; `exterior=True` computes "the exterior thickness (a.k.a. reach)" — VERIFIED [trimesh.proximity](https://trimesh.org/trimesh.proximity.html). VERIFIED-LOCAL on a unit cube at face centres: ray → 1.0, max_sphere → 0.667.
- MeshLib: `computeRayThicknessAtVertices(mesh, progress)` "returns the distance from each vertex along minus normal to the nearest mesh intersection (or FLT_MAX if no intersection found)"; `computeInSphereThicknessAtVertices(mesh, InSphereSearchSettings, progress)` "returns the thickness at each vertex as the diameter of the maximal inscribed sphere"; `rayInsideIntersect(mesh, MeshPoint|VertId, rayEnd)` "nearest intersection between the mesh and the ray from given point along minus normal (inside the mesh)"; `computeThicknessAtVertices` is marked `MR_BIND_IGNORE` (not in Python) — VERIFIED [MRMeshThickness.h docs](https://meshlib.io/documentation/MRMeshThickness_8h.html) and VERIFIED-LOCAL (`InSphereSearchSettings` fields: `insideAndOutside, maxIters, maxRadius, minAngleCos, minShrinkage`; unit cube vertices: ray 1.732 = body diagonal, in-sphere 0.866).
- PyMeshLab `compute_scalar_by_shape_diameter_function_per_vertex(rays=64, cone_amplitude=90)`: "measures the distance from a point on the surface to the nearest point on the object's opposite surface. It can be used to estimate mesh thickness" — VERIFIED [filter list](https://pymeshlab.readthedocs.io/en/latest/filter_list.html); VERIFIED-LOCAL per-vertex values on a unit cube 0.639–0.663 (read via `vertex_scalar_array()`).
- Open3D `RaycastingScene.cast_rays` (returns `t_hit`) and `compute_signed_distance`/`compute_occupancy` work CPU-only on arm64 (VERIFIED-LOCAL), providing the primitives for a custom inverted-normal ray thickness or SDF erosion test.
- pcu `RayMeshIntersector` (embree) and `signed_distance_to_mesh`; pysdf `SDF(verts, faces)(points)` for dense SDF sampling (VERIFIED-LOCAL, [pcu README](https://github.com/fwilliams/point-cloud-utils), [pysdf README](https://github.com/sxyu/sdf)).
- SDF/offset-based thin-feature detection: MeshLib `offsetMesh`/`generalOffsetMesh`/`thickenMesh` and OpenVDB level sets support negative offsets (erosion); OpenVDB's level set has a configurable narrow band (`halfWidth`) — VERIFIED names ([MRMeshThickness docs](https://meshlib.io/documentation/MRMeshThickness_8h.html), [MeshToVolume.h](https://www.openvdb.org/documentation/doxygen/MeshToVolume_8h.html)).
- Blender 3D-Print Toolbox "Thickness" check and slicer thin-wall detection (PrusaSlicer "Detect thin walls", Orca/Bambu "Detect thin wall", Cura Arachne `min_wall_line_width`/`fill_outline_gaps`): see §2b (sub-agent material).

### Inferences
- Ray thickness measured at vertices is unreliable at sharp corners (the 1.732 body-diagonal result); sample at face centroids or dense surface samples and take robust statistics (e.g. 5th percentile) rather than the minimum.
- Inscribed-sphere diameter is the conservative, geometry-faithful "wall thickness" (it equals the true wall for slabs and is lower-bounded at corners); SDF erosion by t/2 (checking that the eroded solid is non-empty and retains components) is the most deterministic global test for "nothing thinner than t", at voxel cost.
- Thin *features* (pins, text) need a different test from thin *walls*: component-wise inscribed sphere or erosion, since a ray along the normal of a 0.5 mm pin still returns the pin diameter but ray tests do not flag unsupported slender geometry.

### Gaps
- No ready-made Python package found that outputs a slicer-style "thin wall map" with FDM nozzle semantics; all options above return per-point scalars that the gate must threshold.
- Performance of each method on multi-million-triangle meshes not measured.

## 5. File formats: STL vs 3MF vs OBJ vs AMF vs STEP; 3MF core/extensions and how to write 3MF from Python

### Takeaway
3MF (ISO/IEC 25422:2025; Core 1.4.0, Feb 2025) is the only format that carries units, multiple objects with transforms, metadata and materials and whose core spec defines mesh validity; STL has no units/colour and a binary/ASCII ambiguity; AMF (ISO/ASTM 52915-20) is still read by Prusa/Bambu/Orca but is little used; STEP (B-rep) is imported by PrusaSlicer, Bambu Studio and OrcaSlicer via OCCT. From Python, `lib3mf` 2.5.0 (BSD, universal2 wheel, ctypes) writes spec-conformant 3MF and validates manifold/orientation; trimesh writes 3MF but always as millimetres, without metadata or colours. Slicer "project 3MFs" add vendor `Metadata/*.config` parts and (Bambu/Orca) Production-extension sub-models under `3D/Objects/`.

## 7. Testing strategy for a deterministic repair pipeline and available test-mesh corpora

### Takeaway
Open-source geometry libraries test repair with small golden fixtures and invariant assertions (watertight/winding flags, exact volumes, face counts) rather than tolerances; for fixtures, Thingi10K (10k real printing uploads with per-model manifold/closed/solid/self-intersection metadata, pip-installable) is the best fit, with common-3d-test-models for classic clean meshes and ABC for CAD-derived STL/STEP.

### Cited Findings
- trimesh `tests/test_repair.py` loops over fixtures `unit_cube.STL`, `machinist.XAML`, `round.stl`, `sphere.ply`, `teapot.stl`, `soup.stl`, `featuretype.STL`, `angle_block.STL`, `quadknot.obj` (+`featuretype.STEP` if `cascadio` is importable); for non-watertight meshes asserts `returned == mesh.is_watertight` after `fill_holes`; removes first/last faces of watertight meshes and checks `is_watertight`/`is_volume` flip; asserts face attributes keep length; checks that a corrupted cached `face_normals` row survives repair; multibody tests assert exact volumes (`np.isclose(m.volume, 2.0)`, `a.volume * 2.0`), that `fix_normals(multibody=False)` leaves an inverted body alone, area `17.5` for a cube missing one face, and `split(only_watertight=True)` body counts (2 before repair, 3 after); default `np.isclose/allclose` tolerances — VERIFIED [test_repair.py](https://raw.githubusercontent.com/mikedh/trimesh/main/tests/test_repair.py).
- Thingi10K: 10,000 models "collected from an online 3D printing model-sharing database" to "capture problems and artifacts endemic to 3D printing models (e.g., self-intersections, non-manifoldness)" — [arXiv 1605.04797](https://arxiv.org/abs/1605.04797) (2016, older); defect rates listed in §2; PyPI `thingi10k` 1.5.0 (2026-08-18), Apache-2.0 code, each model keeps its own licence; `thingi10k.init(variant='npz'|'raw'|'tetwild', cache_dir=…, force_redownload=…)`, `thingi10k.dataset(num_vertices=(min,max), closed=True, num_components=1, self_intersecting=False, solid=True, license='creative commons', query='…')`, `thingi10k.load_file(entry['file_path'])` → (vertices, facets); "see help(thingi10k.dataset) for all available filtering options" — VERIFIED [PyPI](https://pypi.org/project/thingi10k/), [GitHub](https://github.com/Thingi10K/Thingi10K). Hugging Face card: "Total file size: 70.3 GB" (raw), 12 licence types (e.g. CC-BY-SA 3,680 files, Public Domain 88) — VERIFIED [HF dataset](https://huggingface.co/datasets/Thingi10K/Thingi10K). Installed as a pure wheel here (VERIFIED-LOCAL).
- common-3d-test-models: 1.6k stars; Stanford Bunny, Armadillo, Happy Buddha, XYZ Dragon, Lucy, Cow, Spot, Fandisk (CAD), Teapot, Suzanne, Nefertiti, Max Planck, Igea, Bimba, Homer, Rocker Arm, etc., mostly OBJ in zips; no licence statement, only attributions; nothing stated about watertightness — VERIFIED [GitHub](https://github.com/alecjacobson/common-3d-test-models).
- ABC dataset: "a collection of one million Computer-Aided Design (CAD) models" from Onshape; per model STEP, Parasolid, OBJ (with normals/curvature), feature YAML, STL ("parts and complete"), meta YAML; "split into compressed chunks of 10000 models"; "The copyright of the CAD models is owned by their creators" (Onshape terms); STL triangles "have arbitrary shapes with possibly extreme interior angles"; CVPR 2019 — VERIFIED [ABC site](https://deep-geometry.github.io/abc-dataset/).
- Objaverse-XL: "A Universe of 10M+ 3D Objects", "12x larger than Objaverse 1.0", hosted on Hugging Face; no mesh-quality or licence statements on the landing page — VERIFIED [objaverse.allenai.org](https://objaverse.allenai.org/) (Objaverse 1.0 details not fetched — gap).
- manifold3d exposes `status()` with a full `Error` enum, `volume()`, `surface_area()`, `genus()`, `num_tri()` for invariant assertions (VERIFIED-LOCAL); PyMeshLab `get_topological_measures()` and `get_geometric_measures()` return dicts suitable for golden-value tests (VERIFIED-LOCAL); lib3mf `IsManifoldAndOriented()` provides an independent spec-level oracle (VERIFIED-LOCAL).
- Open3D sampling can be seeded via `o3d.utility.random.seed` (VERIFIED-LOCAL), PyMeshLab Hausdorff uses sampling (`samplenum`) so results vary with sample count ([filter list](https://pymeshlab.readthedocs.io/en/latest/filter_list.html)).

### Inferences
- Recommended test layers: (a) synthetic unit fixtures built in code (cube missing a face, duplicated/degenerate faces, inverted body, two touching cubes, split vertices) with exact expected volumes/areas/flags, as trimesh does; (b) a curated Thingi10K slice (e.g. `closed=False` or `self_intersecting=True`, small vertex counts) asserting post-repair `IsManifoldAndOriented`, `is_volume`, `status()==NoError`, and bounded Hausdorff/volume change; (c) cross-library oracles (trimesh vs Open3D vs lib3mf vs manifold3d must agree on watertight/manifold verdicts); (d) determinism tests (hash of exported STL/3MF bytes equal across two runs) with seeded sampling.
- Keep fixture licences in mind: Thingi10K per-model licences are mostly CC variants; common-3d-test-models has no licence statement, so use it only for local tests, not redistribution.

### Gaps
- No evidence found of property-based testing (e.g. Hypothesis) in the surveyed geometry libraries; the Thingi10K paper's full statistics table and Objaverse licensing were not fetched.
